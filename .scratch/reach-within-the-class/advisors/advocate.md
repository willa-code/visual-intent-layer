# Independent review — sceptical user advocate

Lens: I judge every option by what the human meets at the moment of pointing — a mark, a sentence, or a wall — and treat any refusal or extra act as a cost the recommendation must repay.

DECISION 1 — (c): no unasked scroll. Keep the target, refuse in words with the cause, and offer one act on its own row that restores the offset the Annotation itself recorded and re-resolves.

WHY: The scroll position that materialised the row is already stored per Target (`renderedGrounding.boundingBox.scrollX/scrollY`, schema/envelope-v0.3.schema.json:381-385), so restoring it is not a new capability, it is reading back the evidence the human already gave; that is what makes the recovery cheap. Option (a) is not neutral: an unasked scroll either falsifies the record already written or moves the state the human was reviewing, which is the act `design.md` forbids for reload ("never swaps the artifact out from under an open card or an open draft", design.md:249-252; "Reloading the artifact without being asked", design.md:456). Option (b) alone is also wrong: a row that says only "not found" under a row the human can see is the silence `.scratch/reach-within-the-class/spec.md:22` exists to end, so the refusal must name its cause and carry a recovery — and `VISION.md:40,47` says the burden moves into the surface, not into a wall.

BOLDER: Restore the recorded offset automatically at resolve time, but only when the top-level address and the revision both match the Annotation's own record, and say it in one notice — under those two conditions the movement reconstructs the state the Annotation names rather than changing it, which is the one case the default cannot distinguish and therefore must not assume. Alongside it, capture the row's own virtualized key (`aria-rowindex` / `data-index`) as an anchor when it exists, so re-finding the row stops depending on geometry at all.

DECISION 2 — (c): a structural bound read first — depth 8, 5000 elements total across the composed tree with the top document enumerated before any frame or shadow root — plus a stall guard that reports itself as a stall and is never the binding bound. Reaching the bound blocks no gesture: pointing (`layer.ts:241`) and boxing (`layer.ts:277-289`) never consult the candidate list; the rail states the artifact exceeds what the surface reads, and each target outside the bound resolves as unresolved with that reason and the existing `RepointAction` (design.md:264-318).

WHY: 2000 per document is the shipped, already-human budget (`src/ui/artifact/grounding.ts:199`), so preserving the top document's share means no artifact that resolves today breaks. A per-frame budget with no total makes the cost multiplicative (100 frames x 2000), and depth alone produces an asymmetry the human cannot explain ("my card resolves, the same card one component deeper does not"), which is why the total is the binding constraint and depth only stops pathology. Cranking the bound to zero by refusing the whole artifact would remove a capability the human still has, and "resolve lower" is the approximation `design.md:419` forbids; a wall-clock bound as policy is worse still, because the same artifact would resolve differently on the reviewer's laptop and desktop and nothing on screen would say why.

BOLDER: Make the bound self-relieving: when a target falls outside it, the surface offers the drawn Area as the fallback on that same row — the one target that never depended on traversal (`CONTEXT.md:115-116`) — so the human's next act is the gesture they already know instead of a re-point against the same list that will fail again.

DECISION 3 — (a): the Area encloses exactly what is geometrically inside it across open shadow roots and same-origin frame interiors, with boxes mapped into the reviewed viewport, and it never reports an empty area where it truly could not read.

WHY: The Area is the human's own rectangle and the only target whose meaning is entirely theirs, so printing "A drawn area enclosing nothing the artifact owns" (`src/ui/artifact/layer.ts:277`) under a rectangle that visibly covers a shadow-rooted card is exactly the reading-as-nothing-there failure `spec.md:22` was written to fix. The obvious version of (a) is a trap worth naming: `enclosedElements` tests raw `getBoundingClientRect` values in the current document (`layer.ts:288`), and a nested document's rects live in the frame's own coordinate space, so unmapped containment would enclose frame content nowhere near the rectangle — a silent mislabel, which is worse than a refusal. Where a region cannot be read, the reason must be the true one: in a saved-HTML artifact a nested frame never loaded because our own policy blocks it (`src/artifact/fidelity.ts:224`; `SECURITY.md:61`), which is a different fact, with a different remedy, from "the surface cannot read it" in a proxied application (`fidelity.ts:243`).

BOLDER: Give the Area the structure the human actually drew: an Area spanning a shadow-rooted card and the frame beside it records each readable root's own address and its own enclosed set, so the agent receives per-boundary direction instead of one flattened list — no new control and no extra act, and the existing "and N more" disclosure (`layer.ts:277-278`) counts the unreadable region too.

DECISION 4 — (b): keep `runtimeState.address` as the artifact's own address and add an ordered frame chain — each entry the frame's own base-relative address plus its scroll — compared element by element, in one version bump.

WHY: A nested layer computes `addressOf()` from its own `window.location` (`src/ui/artifact/layer.ts:184-192`), so a frame target's address is already the frame's path; landing that in the single existing slot (`schema/envelope-v0.3.schema.json:253-263`, `additionalProperties: false` at :256) loses the artifact's own address, and `deriveResolutionLabel`'s test (`src/resolution/model.ts:30-34`) would then compare a frame path against the shell's top-document address (`src/ui/app.ts:1054`) and fire "May exist only in a state no longer on screen" for every frame target even when nothing moved — a false derived label is worse than silence, because it sends the human hunting a state change that never happened. (c) fails at the other end: the row would carry no reason at all, which is the same silence this feature exists to remove. (a) fails `VISION.md:57` and `design.md:20-21`: one string cannot say which of two frames navigated, so one word would carry two claims.

BOLDER: Decide the Evidence shape once: the frame chain is the same slot backlog's unowned "Declared state beyond the address" will need, so add it in a single version bump and let later declared state — an open dialog, a route, a filter, a form value — attach beside it, giving the human three distinguishable causes (the app's address moved, a named frame navigated, nothing moved and the node is gone) from one field instead of two schema expansions.
