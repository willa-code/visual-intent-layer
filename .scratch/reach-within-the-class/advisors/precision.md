# Independent review — precision and trust engineer

Lens: does the decision raise the fidelity of intent a human can express, and never let the product claim more than it knows.

DECISION 1 — (b) refuse, with the refusal said in the right words: never programmatically scroll, and stop calling an unrendered row Deleted

WHY: The operator can only point at what is drawn — the layer takes the pointer's own event target (`src/ui/artifact/layer.ts:316-319`) — so there is no gesture to refuse at pointing time; the unrendered case is always a *later* state change, which makes it Target Resolution's honesty problem rather than a surface refusal (`spec.md:32-34`). Programmatic scroll is the obvious answer and it is wrong twice: `design.md:249-256` forbids moving the artifact under an open card or draft because the revision a note was written against is part of what it means, and scroll is already recorded state (`grounding.ts:160-175`; `layer.ts:205-209`), so a product-performed scroll makes the envelope assert a state the human was never looking at. Today the failure is worse than silence: an unrendered row yields no candidate and `deriveResolutionLabel` returns `deleted` (`src/resolution/model.ts:17-35`) because `state-only` needs an *address* difference (`model.ts:30-33`) that a scroll never produces (`addressOf` carries only path/search/hash, `layer.ts:185-192`) — so the surface currently claims the row is gone. Smallest fix: gate that label on the recorded state as a whole — `CONTEXT.md:127-128` already defines Runtime State Evidence as including viewport and scroll, so widening `model.ts:30-33` from address to state is a reading fix, not new vocabulary — and never convert the missing node into a marked candidate (`design.md:419`, `design.md:446`).

BOLDER: keep a target's identity anchors independent of its composed index so the operator's own scroll — which they must perform anyway to judge the revision — restores exactness for free: one fresh extraction at the settled scroll, resolved as a new record that overwrites nothing, upgrades the row from the stated refusal to exact in place, with no re-pointing.

DECISION 2 — deterministic composition: one order, one shared node budget, one stated truncation fact; never a clock

WHY: `nodeId` is a positional index into one enumeration (`node-${index}`, `src/ui/artifact/grounding.ts:208`) and `elementByNodeId` re-derives the element by re-running that same enumeration (`grounding.ts:229-235`), so the composed order must be identical at extraction, at marking and at every later revision or a mark lands on the wrong node — which is why a time bound is disqualifying and the bound must be countable. Keep 2000 as the total across all roots (`grounding.ts:200`) and keep the thresholds untouched (`src/resolution/resolve.ts:42-46`): the tempting "resolve lower" at the bound is forbidden by `design.md:419` and `spec.md:44-45`, and holding the shipped number means no artifact that works today changes behaviour. Cycle safety is not tuning: `frame-src 'self'` (`src/artifact/fidelity.ts:243`) plus injection into every `text/html` response (`src/service/http.ts:1317-1324`) means an artifact embedding its own URL (`http.ts:1161`) or `/app/<session>` nests itself, so a visited-document set and a frame-nesting cap (artifact document plus one frame level) are the same decision as the depth bound. What the operator meets is not a refusal: pointing is unbounded (`layer.ts:316-319`); candidates are still marked from the searched portion (`layer.ts:768-779`), resolution abstains only for targets outside it, and the extraction's truncation is recorded as a fact and stated on the row, because an extraction that stopped early must not be reported as a search that found nothing.

BOLDER: seed the composed traversal order from the previous revision's own resolution record, so the budget is spent first on the composed neighbourhood of targets the operator has actually pointed at; exact matches then survive a cut that would otherwise discard them, at zero operator cost.

DECISION 3 — (a) the Area encloses exactly what is geometrically inside it, across boundaries, with one stated hole where the product cannot look in

WHY: An Area is the operator's own boundary and can never carry Source Provenance (`CONTEXT.md:115-116`), so enclosing shadow-root or same-origin frame content creates no overclaim of the kind the product forbids — the geometry *is* the claim — while refusing it makes the product contradict the operator's own eyes, and the current label already asserts emptiness ("A drawn area enclosing nothing the artifact owns", `layer.ts:279`), which over a frame is simply false. In the shipped class the interiors are reachable: a proxied application's frames are same-origin by construction (`fidelity.ts:243`; `SECURITY.md:71-73`), while a saved-HTML artifact cannot nest a frame at all (`fidelity.ts:224`; `SECURITY.md:61`), so the residue is not a "cross-origin interior" but a frame that never loaded, which the surface should state as its own case (`design.md:278`, `policy-blocked`) rather than as an unaddressable region. The conservative answer (b) misreads "never claim more than it knows": that rule forbids inventing contents, not declining to see them, so the Area keeps the operator's rectangle and states the one overlap it cannot enter — a closed shadow root or a blocked frame box — without enumerating anything inside it. The work is real: frame coordinates must map into the reviewed viewport (`spec.md:28-31`), the current enclosed test is strict containment with a five-element cap (`layer.ts:293-309`, `layer.ts:20`), and the stored selectors (`layer.ts:270`) are light-DOM paths that climb `parentElement` (`grounding.ts:90-104`), so taken from inside a boundary they are ambiguous against same-named nodes in the artifact document.

BOLDER: store boundary-qualified anchors in the Area itself, so a rectangle the operator drew survives content moving inside a frame, re-finds the same interior after a revision, and tells the agent which document the region belongs to — the most precise mark the human owns should not lose that precision at a boundary.

DECISION 4 — (d) add a structural frame path plus that document's own address as a v0.4 addition, with every existing field keeping its exact shape

WHY: Folding the frame address into the existing string (a) redefines a word the schema already defines narrowly, "Address of the artifact relative to its own base" (`schema/envelope-v0.3.schema.json:258-260`), and that string is compared to the address now on screen by `model.ts:30-33` via `src/ui/app.ts:600-604`; a composite would report "different" without saying which document moved, and a nested layer computes its own address against the proxied base (`layer.ts:185-192` with `http.ts:1318-1323`), so a frame at the same relative path is indistinguishable from the artifact document. Leaving it (c) is not neutral: the schema's own description promises the state the Target was pointed at (`schema/envelope-v0.3.schema.json:253-254`), so a frame target would be under-recorded while the field still asserts it — the precise failure this lens exists to stop. The extension is a version bump with precedent (`schema/envelope-v0.3.schema.json:5`), shaped as one evidence record per document reached through: the top document's `runtimeState` unchanged, plus the frame path, that document's address and its own scroll and viewport — which also gives the unowned "Declared state beyond the address" item one place to land instead of a third shape (`.scratch/backlog.md:88-92`).

BOLDER: make the frame path a Rendered Grounding anchor rather than only state evidence, because the same path is what re-finds the target after a revision and what qualifies an Area's stored selectors (`grounding.ts:90-104`, `layer.ts:270`); without it a frame target's unqualified selector can score a capped exact against a lookalike in the artifact document (`resolve.ts:101-140`, `isExactMatch` at `resolve.ts:169-176`). One new fact serves re-finding, the Area and Runtime State Evidence, and the operator still does nothing.
