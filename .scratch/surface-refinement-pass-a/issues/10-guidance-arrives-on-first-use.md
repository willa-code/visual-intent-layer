# 10: Guidance arrives on first use, once

**What to build:** Guidance becomes a **coachmark** anchored to the control it explains — two lines at most, shown one at a time, triggered by the first real use of that control rather than at launch, dismissed by one worded dismissal, and remembered per device rather than per artifact.

Today a three-sentence paragraph sits at the bottom of the stage until dismissed, pointing at nothing, styled exactly like product chrome, and remembered per artifact — so a Builder-Reviewer opening ten files is taught ten times.

**Blocked by:** None (can start immediately)

**Status:** done

- [x] No guidance is shown at launch, when an artifact is first opened
- [x] A coachmark appears when the control it explains is used for the first time, anchored to that control
- [x] At most one coachmark is present at a time, and each is at most two lines
- [x] Each carries one worded dismissal, reachable and operable by keyboard, and dismissing it removes it
- [x] Dismissal is remembered for the machine, so opening a different artifact does not show the same coachmark again
- [x] The overflow menu offers one entry that clears all guidance, and after using it no coachmark appears until guidance is restored
- [x] A coachmark is visually distinguishable from the interface it sits on, so it cannot be mistaken for a control
- [x] A dismissed or never-seen coachmark removes no capability and is never the only route to a control
- [x] Escape dismisses a coachmark before it closes anything else
- [x] The first-run paragraph is gone, and no instruction sentence about a self-teaching control remains anywhere in chrome
- [x] A test uses a control, asserts the coachmark, dismisses it, opens a second artifact, and asserts it does not return
