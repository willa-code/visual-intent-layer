# Steering is a convention, not a negotiated capability

An MCP server cannot put anything into an agent's running turn: the specification gives it no message pattern for that, and cancellation is cooperative, so even a stop is a request rather than an act. Delivery therefore has exactly two forms — returning a held tool call early, which is guaranteed and already implemented, and an agent-initiated call, which is a convention the product publishes. Steering Intent and Review Interruption are the second form: seen at a Check-In between the agent's own steps and never mid-step. This retires ADR-0008's "active-turn steering" clause while leaving its negotiation mechanism intact for Embedded UI and subscriptions, and moves the capability declaration out of dead code into the tool schema so the seam it describes is reachable.

**Considered Options:** Keeping a `steering` capability flag and honouring it when a host declared it was rejected because `deliveryPlan`'s strategy was computed, returned and never branched on anywhere, so the flag gated nothing — it told the Builder-Reviewer that something was delivered immediately while the code did exactly what it did for every other intent. Building a push channel was rejected as out of scope and outside what MCP sanctions; polling through the Tasks extension is the one push-free pattern the specification does offer, and that is a form of Check-In rather than an alternative to one. Deleting steering and interruption together was rejected because amending work in flight and stopping it are the two things a Builder-Reviewer most wants from the surface, and a request that waits is honest where a control that pretends is not.

**Consequences:** `deliveryPlan` and `DeliveryPlan` are deleted; the capability declaration keeps `embeddedUI` and `subscriptions` and loses `steering`. A Check-In call becomes part of the tool surface, which blocks the amend, stop and convention tickets. The surface states which delivery channel applies and when the agent last checked, so a convention nothing honours is visible rather than assumed. `design.md` §4 requires the act to be a request, never a claim that work stopped. The `?cap=` session token in `src/service/http.ts` is an unrelated meaning of "capability" and must not be conflated with host capability.
