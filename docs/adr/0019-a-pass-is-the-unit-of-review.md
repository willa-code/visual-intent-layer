# A Pass is the unit of review, and only the Builder-Reviewer closes it

Direction is delivered and answered a Pass at a time: one set of Annotations, and the artifact revision that answers them. A Pass is a first-class object carrying a state — open, in flight, ready, closed — its member Annotations, and the revision range it spans, and only the Builder-Reviewer closes it. An agent changing the artifact, acknowledging a batch or checking in may move a Pass to ready and never to closed. This is the single fact that lets the surface answer "whose turn is it?" without a sentence, and it is why an Annotation is stamped with the revision the Builder-Reviewer was actually looking at rather than the revision the file happens to have.

**Amended by ADR-0024:** Pass-level reporting names evidence, not accomplishment. The outcome words are *changed*, *same* and *not found* rather than *answered*, *untouched* and *gone*, and the artifact carries no pass-outcome marks: every mark on the artifact is something the Builder-Reviewer can act on.

**Amended by ADR-0025:** A verdict is reversible, and a closed Pass is a record. Changing a decision is one act that reopens the Pass it closed, a Pass may be closed with members still undecided and those read as never decided, and a closed Pass refuses later resolution writes.

**Amended by ADR-0026:** Another Pass opens a new Pass carrying the members that have not been accepted and not been abandoned, and closes the Pass it answered with its outcome and result revision frozen.

**Amended by ADR-0028:** A Pass the agent has not collected can be taken back, and collection is the boundary: `collectedAt` is stamped wherever the agent reads a delivery, a withdrawn Pass returns its members to the queue, and a read delivery is changed only by a Replacement.

**Corrected 2026-09-18:** The state list above names `open`, which no code path assigns — every Pass is created at `in-flight` — and omits the state a withdrawn Pass ends in, rendered "Taken back". The reachable states are in flight, ready, closed and taken back.

The repository already has the identity and discards the lifecycle. `DeliveryBatch` carries an `envelopeId`, an `idempotencyKey`, a host, a delivery `intent`, an `annotationIds` list, the envelope and a timestamp, and **no state at all**, while `SessionSnapshot.batches[].status` in the browser client declares a `status` the server has never sent. The consequence is a surface that cannot say a Pass is in flight, cannot say a revision answered four of five Annotations, and instead restates the delivery convention in prose in four separate places on one screen.

**Considered Options.** A per-Annotation lifecycle with no Pass, which is what exists now, was rejected because it leaves the surface unable to distinguish *answered* from *untouched* from *gone*, and forces the delivery convention to be re-explained in the rail head, the rail footer, the Stop action and a toast. Letting the agent close a Pass, or closing one automatically when its Annotations reach a terminal state, was rejected because only a Builder-Reviewer completes intent (ADR-0012) and because a revision arriving is not evidence that anything was addressed: the product has no completion signal from an agent at all, only `check_in` and `acknowledge_intent`. Deriving closure from the existing attention count was rejected because that count already conflates three unrelated claims — unresolved targets, Annotations written before the current revision, and a non-empty queue — and a fourth meaning would not survive.

**Consequences.** Pass state is new server-side capability, and closure becomes a Builder-Reviewer act rather than a derived one. `attentionItems` splits into the three claims it was summing. `Another Pass` becomes the Pass-level act and `Not Fixed` the per-Annotation verdict, because one word was carrying both. Pass-level reporting may say *answered*, *untouched* or *gone* — all anchor-level facts derived from Target Resolution — and may never claim that an agent fixed anything, because nothing reports that. Reporting a Pass outcome requires a snapshot per adopted revision, which today is written once, at open. The delivery `intent` union loses its dead `draft` member, which `markDelivered` already refuses. ADR-0012 is extended rather than reversed: verification still completes an Annotation, and the Pass is what a Builder-Reviewer closes around it.
