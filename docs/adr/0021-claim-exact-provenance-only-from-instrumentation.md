# Claim exact source provenance only from instrumentation

**Status:** accepted

`exact` Source Provenance is claimed only when an instrumented artifact supplied a source location. The adapter read React fiber `_debugSource`, which React removed in 19; React's replacement `_debugInfo` is `null` in practice, the removal issue is closed as not planned, and `captureOwnerStack` is unavailable at click time and returns a component-level stack that cannot distinguish sibling elements. Reading framework internals therefore cannot support the product's own primary stack, so the fiber read, the exported Vite plugin that pointed at a script nothing served, and the `stableRuntimeId` read and scoring anchor are all deleted. In their place the product reads a build-time source-location stamp off the Target's element and reports `unavailable` when none is present.

**Considered Options:** Keeping the fiber read was rejected because it is false for every React 19 app and React states that its fiber structure breaks between releases, so the product would be promising stability it cannot have. Owning the per-framework transforms was rejected for now because that surface — one transform per framework, per bundler, dev-only — is what the deleted plugin stub pretended to be, and maintaining other people's compilers is not this product's job. Deriving locations by reverse-mapping source maps was rejected because no framework exposes the generated position of a clicked element to page JavaScript, so source maps cannot close the first half of the problem.

**Consequences:** The reader accepts a stamp attribute so the product owns the contract, not the transform, and a documented working instrument (`code-inspector-plugin`, which stamps `data-insp-path`) can be cited as one way to produce it rather than taken as a dependency. `Provenance Confidence` names the condition in its own entry. Stamped coverage is per-element rather than per-application, because an instrument escapes a known set of non-visual tags, so the claim is per-Target. The mutation benchmark must measure the false-confidence rate of the instrumented path, not only its hit rate.
