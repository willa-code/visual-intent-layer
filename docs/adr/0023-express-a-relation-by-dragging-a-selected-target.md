# Express a relation by dragging a target that is already selected

**Status:** accepted

The surface expresses Relational Intent through a gesture over a set rather than a tool: `Shift` extends a selection into a set of at most eight targets, and a drag that begins on a target already in that set moves a ghost and infers one relation, shown back as one plain sentence before release. The operator vocabulary is the one ADR-0016 reduced to the relations that have a real gesture — ordering, alignment, equal spacing, containment, shared property and comparative size. The stored relation is the desired relationship, with no pixel field anywhere, and the artifact's source and authoritative DOM are never changed by a drag. The ghost plus the sentence is the Intent Preview the product promised: a reversible visual proposal shown before it is recorded, not a separate capability.

**Considered Options:** Explicit handles on a multi-selection — the model Figma users already know — was considered and refused, because it costs a new selection-bounds component for a capability the two-tile island can already carry. A relation type or operator picker was already refused by ADR-0016, because a relation must have a real gesture rather than be chosen from a list. A freehand pen, highlighter, arrow or shape palette was refused because a stroke layer needs portable semantics for "this squiggle means something", which Relational Intent already expresses better. Deriving relations from a toolbar mode was refused because the `Arrange` tool it would restore was undiscoverable: it did nothing until two targets were already selected.

**How the family is chosen.** Four families are inferred from the drag's geometry: containment when the dragged target lands inside another, ordering when it is dragged past another along the dominant axis, and alignment when an edge or centre line comes into line with another. Three families cannot be discriminated by geometry, because a move cannot express a size, a property or a rhythm, so they are declared with a key held through the drag: `Alt` for equal spacing, which needs three or more targets, `Ctrl`/`Cmd` for a shared visible property, and `Shift` for comparative size, whose dominant axis chooses width or height. `Shift` is free to mean this during a relation drag because it is the set modifier only on click and box, and the target being dragged is already in the set.

**Consequences:** This supersedes the deferral in `design.md` §11 amendment 4, and §5, §6 and §7 are amended in the same change. The envelope's `relationship` definition is unchanged, because it was never the missing part. `CONTEXT.md`'s Relational Intent, Visual Intent Layer and Intent Preview entries describe the shipped capability, and Intent Preview is named as the ghost plus the sentence. `README.md` is restored to describe gathering several targets into one Annotation. The verification skill's relational-intent feature file stops saying "deferred" and gains a `relate` drive, and the Lever regains `select --add`. Two decisions are recorded here rather than left implicit. A drag that begins anywhere other than an already-selected target behaves as the artifact does, so text selection is unaffected, and geometry that infers nothing records nothing and says so in words. Relational Intent has no keyboard route, and its absence is stated rather than papered over: no target of any kind is reachable by keyboard today, so a relation-only route would be the product's only keyboard targeting and would misstate the surface. That route is reopened when keyboard targeting exists.
